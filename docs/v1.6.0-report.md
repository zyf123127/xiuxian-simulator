### 1. 文字清晰度修复（最终组合与依据）

**症状**：v1.5.0 桌面端在 Windows 125%/150% 显示缩放下文字发虚。

**根因与依据**：v1.5.0 关闭 high_dpi，1280×720 位图由 DWM 拉伸到物理像素（`src/main.rs:24-27` 注释载明"DWM 位图拉伸是 v1.5.0 发虚主因"）。【代码】

**最终组合（四件套）**：

| # | 改动 | 位置 | 依据 |
|---|------|------|------|
| ① | 桌面开启 `high_dpi: cfg!(not(target_arch = "wasm32"))`，miniquad 走 `SetProcessDPIAware()`，字形按 dpr 原生栅格 | `src/main.rs:27` | 【代码】；wasm 恒关——真机 dpr≈3 会按比例放大字形图集，有爆图集/黑块风险（rust-macroquad-game skill 第 9 节），不做评估不启用 |
| ② | 首帧 `request_new_screen_size(1280.0, 720.0)`（`#[cfg(not(target_arch = "wasm32"))]` 门控）：high_dpi 后窗口按物理像素开窗，150% 缩放首帧 `screen_width()`≈853，请求 1280×720 **逻辑**尺寸后 macroquad 内部 ×dpi → 客户区 1920×1080 物理像素；次帧起 `screen_width()==1280`、`cam.rs` fit==1 零改动、窗口视觉尺寸与 v1.5.0 一致（100% 缩放下为 no-op） | `src/main.rs:43-51` | 【代码】；首帧 ≈853 属预期（request 于 next_frame 后生效，代码注释引用 macroquad window.rs 原文） |
| ③ | `MIN_FONT=14`，measure/txt 两处 `size.max(MIN_FONT)`，小字号不再低于 14px | `src/ui.rs:19,22,29` | 【代码】 |
| ④ | H5 侧 canvas `image-rendering: pixelated` 最近邻上采样（wasm 侧 `dpi_scale()` 恒 1、backing=CSS 像素，dpr>1 浏览器双线性放大致虚；pixelated 保像素风锐利） | `web/index.html:27`（带注释） | 【代码】；既定取舍：H5 渲染分辨率仍为 CSS 像素，dpr>1 不提升物理清晰度 |

另配事件弹窗等布局的行距与对比度微调（流水线实现摘要载"行距 28/24+对比度两处"，撰写时未逐行复核，不作代码引用）。

**实测效果**：本机 150% 缩放下终局验收 52 张截图全为 1920×1080 物理像素原生渲染、字形边缘锐利；`shot_024` 坊市底部 14px 小字「（筑基丹/破境丹/护神丹在突破与渡劫时自动生效）」经目验完整清晰可读。【截图 shot_024 目验】

## 四、设计与平衡要点

1. **单层无栈弹层**（menu.rs 头注释定稿）：`Game.submenu` 持有当前弹层，Esc/取消/返回三路关闭，不引入弹层栈——复杂度与触屏误触面都最小。
2. **门闩而非全局输入锁**：`sub_fresh` 只屏蔽置位帧一帧的行按钮命中，代价 O(1)，且不拦其它输入路径。
3. **主题 0 = v1.5.0 逐值等价**：老档迁移后首屏地图无感知变化；`node_xy` clamp 保证任意 jitter 不越画布、不压节点文字。
4. **换幕双参数正交**：`map_region`（wrapping 递增，mod 5 循环五主题）决定"画风"，`map_seed`（LCG 演化）决定"布局细节"——同一地区反复造访仍有差异。
5. **好感曲线温和**：满档需 95 好感；被动积累（任务 +3/购丹 +1）与主动投入（赠礼 +2、价格 500×(1+档) 递增）并行，赠礼通胀对冲线性刷好感；增益封顶温和（任务收益 +25%、丹价 −15%、双修 +35%）。
6. **道侣好感只升不降**：`max` 语义 + 好感挂玩家—NPC 体系而非具体人名，换伴侣不清空（game.rs:2933-2937 注释明示设计意图）；遗泽"有伴才承接"避免无伴蹭加成的文案歧义。
7. **修炼数值单一乘链**：`cult_gain_per_year` 是唯一出处，弹层预告=实际所得（shot_029 副标与日志同为 +9.8），杜绝两处口径漂移。
8. **破境一步变两步**：破境收进修炼弹层二次确认，为定稿取舍；数字键 2 保留直达路径缓解操作变长。
9. **硬约束全部守住**：零新增 crate；存档只加字段、缺键默认旧档可读；Scene 枚举未动（新场景 0 个）；`self.life.as_mut()` 可变借用均圈在小作用域（revenge_win/buy_pill/gift_npc 等处实读确认）。

## 六、遗留问题与建议

1. **真机 H5 首测项（上架后必须回归）**：存档→刷新→读档回环（最高优先）；触屏点击底栏/弹层/地图节点；音频播放；dpr>1 下 pixelated 上采样观感与帧率；WebView 缓存穿透（GAME_VER 生效性）。本轮格式层已由单测锁死、介质层与首包已实测链路相同，但端到端未重跑。
2. **事件弹窗新布局无确定性入镜**：流水线仅算术核验（行 `316+i*74`、3 行 ≤526<560 面板高）+ 单选项帧（道友论道）目验；三选注入卡因 RNG 门控未确定性入镜。建议后续在 autopilot 增加确定性事件帧。
3. **模拟内反杀宿敌同样触发换幕**（共用 spawn_next_neme，代码注释明示为设计口径）：shot_047 的西漠前提是 46 前无模拟斩敌（本轮实测成立，非确定性保证）；若追求剧本化冒烟镜头，需将换幕口分流。
4. **底栏破境一步变两步**：定稿取舍（数字键 2 缓解）；建议观察玩家反馈再决定是否回退。
5. **H5 物理清晰度取舍**：pixelated 只改上采样滤镜，渲染分辨率仍为 CSS 像素，dpr>1 不提升物理清晰度——既定方案（规避 wasm 真机 high_dpi 的字形图集放大/黑块风险，skill 第 9 节）。未来如上真机 high_dpi，必须 cfg 分流并专项评估图集上限。
6. **make_promo_icon.py 未适配 1920×1080 镜头**（裁切按 1280×720 调校）：未来重生成 promo/icon 前须先改裁切参数（发布说明已注明）。
7. **存档插件握手值**：xx_storage version:1 与 save.rs 恒定一致；未来存档格式破坏性变更需两端同步 bump。
8. **冒烟前提**：镜头编排以净档为前提（GF_CLEAN 删档），与 v1.5.0 一致；`xiuxian_save.txt*.bak` 两份 untracked 备份可在发布后清理。
