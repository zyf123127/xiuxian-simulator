# 《凡人模拟·轮回模拟器》性能卡顿问题分析与解决报告

- 日期：2026-10-25　版本跨度：v1.9.24 → v1.13.0（五轮迭代）
- 结论先行：**用户实测确认"似乎不怎么卡顿了"**。本报告把五轮"莫名卡顿"攻坚的根因、测量证据与修法整理成可复用经验；同款经验已沉淀到技能 `macroquad-bug-hunter`（症状→根因映射表·性能类）与 `rust-macroquad-game`（性能与内存章）。
- 证据标注约定：**【实测】**=会话内实际执行的测量命令/输出；**【代码】**=源码行号；**【推算】**=按调用频率与尺寸推理（未直接采样）。

---

## 〇、一句话总结（给赶时间的人）

macroquad（miniquad wasm）H5 游戏"莫名卡顿"的头号嫌疑人**不是粒子特效，而是字体图集**：任何"首见"的 (字符, 字号) 组合都会触发字形栅格化并把整张图集重新上传 GPU（2048² 时一次 16MB）。动态字号动画 = 逐帧新字号 = 逐帧 16MB 上传；文字密集面板首开 = 一次几十次上传的长任务。先做字号离散化 + 预热 + 脏矩形上传，再谈其它。

---

## 一、测量方法（先测量后动手，本报告全部结论的来源）

1. **Hook WebGL 上传 + 长任务**（桌面 Chromium，一次定位全部尖峰）【实测】：
   在 console 注入 `texSubImage2D/texImage2D` 包装，记录 ≥65536px² 的上传（尺寸/字节）；配 `PerformanceObserver({entryTypes:['longtask']})` 记录 >50ms 阻塞。开关面板各测一遍，"首开 vs 二开"差异即字体缓存 churn 的直接证据。
2. **wasm 线性内存**：`wasm_exports.memory.buffer.byteLength`（页面 evaluate）——看常驻与增长斜率。
3. **常驻 dbg 仪表**（?dbg=1）：`fr`（距上帧 ms）+ `G/U`（字形栅格化/图集上传总量与本帧增量，vendor text.rs/atlas.rs 原子计数）——验收口径"banner 弹出 0.6s 动画期逐帧增量 +0/+0"。
4. **每帧分配审计**：`grep -c 'format!'` 等静态计数后**逐行分类"每帧执行 vs 事件执行"**（本轮实测：game.rs 123 处绝大多数是事件时执行，draw.rs 51 处中约 14 处每帧执行——游戏逻辑不是热源，绘制路径才是）。
5. **PSS 黑盒对比不可行**【实测】：夸克浏览器主进程自身随时间涨数百 MB（空白页 60 秒内 383→731MB），游戏增量被完全淹没。手机侧只信 `wasm_exports.memory` 与 dbg 仪表。

## 二、根因逐项（按最终严重度排序）

### 根因 1【帧率·最高优先】字体图集 churn——"点按钮卡一下"的直接根因

- **现象**：点击功能按钮到面板出现之间明显迟滞；横幅演出期间逐帧掉帧。玩家原话"进游戏后点按钮卡顿""怀疑与主角动态特效有关"。
- **机制**【代码】macroquad 按 (字符, 字号) 逐对缓存字形：首见即栅格化入图集并置 dirty，而每个字形绘制都调 `atlas.texture()`，dirty 即把**整张图集**字节 `texture_update` 上传 GPU（2048²=16MB/次，4096²=64MB/次）；图集封顶填满后原地清空（sprites.clear），整套 UI 字形随后重栅格化。
- **实测**【实测】图集 2048² 态下：坊市首开 79-83 次整图上传 ≈1.3GB、longtask 728ms；烙印 67 次/1072MB/615ms；人物页 51 次/816MB/446ms；帮助 14-16 次/122-156ms；**同一面板第二次打开 0 次/0 longtask**（缓存完全有效）——全部开销都在首开。手机上传带宽慢 2-4 倍（推算）→ 0.3~2s 级迟滞，与体感吻合。
- **修法**（四招，全部落地 v1.10.0/v1.11.0）：
  1. **字号离散化**：动画字号禁用 `(54.0*scale) as u16` 连续取整（0.6s 动画=每帧新字号），改为固定档位 {54,60,66,72}【代码】draw.rs banner；
  2. **事件帧预热**：`ui.rs::prewarm_text(text, sizes)` 在弹出/打开事件帧把该面板全部文案×字号档一次栅格化，动画帧零缓存 miss【代码】game.rs show_banner / 各面板打开口；
  3. **字号收敛**：全 UI 12 档字号收敛为 {14,16,18,20,24,28} 六档（106 处调用点按"向下就近取档"机械替换），(字符,字号) 组合数砍半以上；
  4. **菜单期后台预热**：`panel_warm_step` 原子游标每帧预热 40 字形（高频文案 top300×6 档 ≈1800 组合，约一秒铺完），玩家点开任何面板时字形早已在图集里。

### 根因 2【内存·高】图集无上限生长

- **机制**【代码】vendor atlas.rs 按设备 MAX_TEXTURE_SIZE 钳制（原 4096），图集 512² 起步翻倍生长；到顶后 reset-in-place 全清。
- **实测**【实测】桌面新会话 2 分钟"全面板巡礼"图集即 512→2048，wasm 堆 19.1→43.3MB（含 16MB 图集 CPU 副本）；手机 4096 上限时图集 CPU+GPU 各 64MiB（合计 128MB）。
- **修法**：上限钳到 **2048**（CPU -48MB + GPU -48MB = **-96MB**），代价是 reset 更频繁——reset 帧配合根因 1 的预热/收敛后不再是持续问题。

### 根因 3【帧率+内存·高】超采样 SS=3

- **机制**【实测】index.html XX_SS=3 → backing = CSS×3：720p 类屏 3840×2160 RGBA 单缓冲 33.2MB、合成双缓冲 ≈66MB GPU 常驻；填充率 9×（全屏 alpha 叠加型 UI 的最大帧率杠杆）。
- **修法**：默认 SS=2（省 ~37MB@720p、填充率 -56%）；**dpr>2 的手机保持 3**（防 v1.9.10 修过的"真机模糊"回归——dpr≥2.5 时浏览器阶段放大 ~1.6× 会发软）；`?ss=` 临时覆盖参数保留供验收。

### 根因 4【帧率·中】每帧堆分配与深克隆

- **实测/代码**：draw_sim 每帧 `g.sim.clone()` 深克隆整个 Life（5 Vec+String+highlights）；draw_inherit 每帧克隆 SimResult；模态卡每帧 clone 卡面+逐选项重建 eff_desc；Reality 每帧 22-28 次小 format!；ui.rs wrap() 逐字符 to_string+measure。
- **修法**：绘制函数借用化（`as_ref()` 只读借用，`&mut` 交互统一后移或"先收集动作后分派"——PanelAct 先例）；模态卡面 (label,desc) 惰性缓存（注意 v1.10.0 曾把 label 与 desc 错位比对致缓存永不命中，v1.10.1 修复——**缓存类优化必须验证"命中路径真的命中"**）；wrap (text,size,maxw) 键记忆化（上限 256 防膨胀）。

### 根因 5【帧率·中】过度绘制（多层全屏半透明叠加）

- **实测/推算**：渡劫场景叠加 3.5-4× 全屏（全屏紫 0.62+四条暗角≈1.1 屏+18 朵雷云 36 圆+flash+日志底）；Reality 2-2.5×。backing 3.5M 像素下每帧 9-14M 混合像素。
- **修法**：静态叠加**预烘焙成小纹理**（暗角 4 全屏矩形→320×180 烘焙 1 quad，逐像素按覆盖带数复现合成 α；雷云 36 圆→双圆合成云团纹理 9 quad）；日志隔行底合并为整块 1 矩形（α≤8/255 肉眼无差）。

### 根因 6【卡顿·一次性 hitch 类】

- **地图底图同步烘焙**：首次进入某区域在**绘制路径**里逐像素烘 1264×480（约 60 万像素）→ 修法：烘焙挪到场景进入口（open_world/travel 预烘，幂等命中缓存）。
- **周天吐纳每 1.6s 同步 localStorage 写**：主线程同步 IO 周期性微顿 → 修法：sync_save 去抖（内存快照即时、磁盘写"UI 边界信号变化即落，否则 ≥3s 一落"，pagehide/visibilitychange 强制兜底）。
- **每帧 life.clone()×3**（draw_world/draw_reality/draw_char_panel）→ 全部移除。

### 根因 7【加载期·"卡"的另一形态】冷加载卡死在加载屏

- **现象**（MuMu/X5 实测，v1.11.0/v1.12.0 复现）：加载屏"已等待 N 秒"计秒先走后停、页面零变化 >2 分钟；r2 双加载的 onReady 决策点结构性不可达（wasm 编译期主线程停滞）。
- **修法**（v1.13.0）：加载停滞看门狗——D1 计秒心跳停摆 ≥20s（计秒 interval 每秒刷心跳，停摆即观测特征直接编码）+ D2 加载层可见且无 wasm 超 120s 保险丝；`wd=N` URL 参数硬上限 2 次防循环；worker 时钟借道抗钳；死因穿越进 errlog。

## 三、排除项（同样重要——防止后人再走弯路）

1. **粒子系统无罪**："怀疑主角动态特效"的直觉是错的——光环 motes 固定 42 只、meteors 每帧生成概率 dt*0.08 寿命 1.1s、sparks 仅事件 burst（≤140）且自然耗散，全部 retain 清理、几何绘制零堆分配。真正的"特效卡顿"藏在**特效的文字**（横幅大字）的字体缓存 churn 里。
2. **game.rs 的 123 处 format! 多数无罪**：绝大多数在事件结算/日志/存盘路径（事件时执行），每帧热源在绘制路径。
3. **PSS 黑盒对比不可行**：夸克自身内存涨数百 MB，游戏增量被淹没——不要再用 dumpsys meminfo 对比游戏版本。
4. **bug_scan 的"字体缺 α⊆"HIGH 是假阳性**：只出现在源码注释里的字符不进渲染。

## 四、最终状态（v1.13.0 验收口径）

- 常驻内存：图集钳 2048（CPU+GPU 各 ≤16MB）+ backing SS=2（720p ≈29MB×2）+ 立绘懒加载（未出场零解码）+ 地图缓存 3 张（≈7MB）；
- 帧路径：每帧零字符串重建（缓存命中）、零深克隆、渡劫过绘 9 quad；
- 首开路径：菜单期 1 秒内铺完 1800 高频字形组合，面板首开从"几十次整图上传/数百 ms longtask"降为脏矩形小上传；
- 用户实测确认不卡。剩余已知项：真机首装的长尾验证由玩家反馈驱动（加载看门狗已兜底）。

## 五、经验清单（十戒）

1. **先测量后动手**：hook GL 上传 + longtask 是"莫名卡顿"的最快定位法，一次给出全部尖峰的量化清单。
2. **字体图集是 H5 UI 性能第一嫌疑人**：动态字号=性能炸弹；文字密集 UI 先查 (字符,字号) 组合数。
3. **"特效卡顿"直觉常错**：几何粒子（零分配）通常无罪，特效的"文字"才是。
4. **每帧分配审计**：静态 grep 只定位候选，必须逐行分类"每帧 vs 事件"。
5. **缓存类优化必须验证命中**（label↔desc 错位比对教训）。
6. **常驻内存按 GPU 纹理算**：图集/backing/立绘×4B/像素，wasm 堆反而是小头。
7. **画质换内存要留 dpr 口**：SS 降档在低 dpr 无感、高 dpr 发软。
8. **同步 IO 出帧路径**：存盘去抖 + pagehide 兜底。
9. **一次性重活挪出绘制路径**：烘焙/预热在事件帧或菜单期做。
10. **手机侧只信 wasm memory + dbg 仪表**：PSS 黑盒被浏览器自身噪声淹没。
