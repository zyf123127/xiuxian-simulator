# 凡人修仙 · 轮回模拟器

Rust + macroquad 开发的**模拟器流修仙游戏**：主角是获得【轮回镜】的凡人，消耗模拟点数推演一生，死后选造化带回现实，不断变强、斩杀宿敌。参考模拟器流修仙小说设定。

![画面](shots/shot_010.png)

## 玩法循环

```
现实主角 → 花 1 点开模拟 → 抽天赋(3选1) → 自动推演一生(可看可跳) → 模拟死亡
   ↑                                                    ↓
   └──── 现实：闭关修炼/突破境界 ←── 选 1 项造化继承(修为/功法/法宝/寿数…) ←┘
                                ↓
                     灵石兑换点数 → 再模拟 → 斩杀宿敌 → 更强宿敌接棒 → 飞升成仙
```

- **现实层**：时间只在操作时流逝。闭关修炼（寿元-1年）涨修为；修为满可突破（轮回镜护持，现实突破不会身死）；寿元耗尽则一世归尘，结算大笔道韵后轮回再起
- **模拟层**：一年一行文字自动刷屏（暂停/缓/快/跳过四档），自动修炼、游历、闭关、突破、渡劫九重雷劫。模拟中的你从现实境界出发——现实越强，模拟走得越远
- **继承造化**：模拟死亡后随机给 3 项选 1（烙印升级后 4 项选 2）：继承修为（模拟所得五成）、功法、法宝、财货、丹药、寿数、道果、气运
- **宿敌系统**：每轮人生随机一名血仇大敌（如"血手人屠·墨荒 金丹中期"），每次模拟都会遭遇——打不过会被一掌拍死；变强后可在模拟中反杀（领悟其招，现实直接授首）或现实寻仇。斩杀得灵石/点数/道韵，更强的幕后之敌接棒，从金丹一路杀到道祖
- **模拟点数**：初始 3 点，1 点一场；坊市用灵石兑换（境界越高越贵）；成就与斩杀宿敌赠送
- **轮回烙印**：道韵购买永久强化——四维属性下限、继承项数、天赋 4选2、点数返还、修炼速度、寿元……代代相传
- **天赋池**：33 种天赋分凡品/灵品/仙品三档，从"灵光初绽"到"混沌道体""雷帝转世""掌天瓶转世"
- **成就**：22 个成就（境界/寿命/财富/斩敌），首达奖励道韵

境界体系（参考《凡人修仙传》）：凡人 → 炼气十二层 → 筑基 → 金丹 → 元婴 → 化神 → 炼虚 → 合体 → 大乘 → 渡劫 → 飞升成仙 → 真仙 → 金仙 → 太乙 → 大罗 → 道祖

## 操作

| 键 | 功能 |
|----|------|
| 空格 | 模拟中暂停/继续 |
| 1 / 2 / 3 | 模拟速度：缓 / 快 / 跳过（瞬间演完） |
| Esc | 关闭面板 |
| M | 山河图（世界地图） |
| C | 角色面板 |
| 鼠标 | 一切按钮 |

## 版本历史

- **v1.9.18**：首开卡顿根治（v1.9.17 真机四截图定案后的收口）——真机实证 v1.9.17 全链工作：首开卡（菜单+进游戏 ~20 秒）→ 游戏内 wedge 评估 14.7fps → 自动重载 → 此后满帧流畅；用户诉求：第一次打开就别卡。根基规律（三次实测）：首开加载慢（wasm 下载+编译）被 X5 容器钳制一切定时器，**重载后缓存热秒开、循环存活**。把重载提到最早时机：**冷启预检**——wasm 就绪后 2 秒起 3 秒窗口统计帧号增量，<45 帧（<15fps，慢设备 ≥20fps 不误触发）即 wedge 实锤，不等用户任何操作立即热身重载（预算内，URL 标记防循环）。用户感受：打开 → ~5 秒内画面自动一闪 → 满帧菜单 → 即点即进；首开卡顿窗口从 ~20 秒压缩到 ~5 秒。修复连带 bug：xxRlUsed 跨 IIFE 引用未定义（xxSim 的 wedge 分支调用 xxWatch 闭包内函数）→ 挂 window。仿真对齐：?wedge=1 冻结 5s→2s（真机首开即钳）。验证：本地剧本 A（正常 60fps 8 秒零触发）/B（首开 wedge 2s 冻结→5s 冷启重载→重载后 64fps）全绿、flow/chaos 回归绿、MuMu 真实安卓环境剧本全链通过（t+9s 已完成热身重载+满帧菜单、t+15s 一次点击进游戏 fr10ms、零噪音）。

- **v1.9.17**：MuMu 模拟器完整复现+验证闭环（用户两轮点名要求的模拟器验证）——v1.9.16 真机日志实锤"帧车夫接管"后仍一卡一卡+大旗又弹：**车夫的 setInterval(1000) 同被容器钳死**（stale>6000 仍触发复活冲击），wedge 态唯一可靠事件源=触摸。MuMu+夸克（真实安卓 WebView）验证游戏代码完全健康（一击即进+60fps 零噪音）→卡顿全部来自 X5 容器钳制。修复策略转向"重载换满帧"（用户三次实测重载后必好）：①**wedge 低帧率自动重载**：快速唤醒成功（=wedge 实锤）后 8 秒窗口平均帧率 <15fps → 自动重载（触摸事件驱动评估，interval 不可靠）；每会话一次预算，用完后车夫+触摸帧保底可玩；②大旗弹出前最后一搏改为直接重载（wedge 态弹"引擎无响应"旗只会让玩家以为游戏坏了）；③触摸同步帧 1→3 发；④`?wedge=1` 仿真参数：5 秒后永久冻结三时钟+车夫禁启+同步帧禁用（真机死透态完整复现），重载过一次后不再冻结（对齐真机"重载后必好"）——MuMu 剧本全链验证：复现卡（唤醒+8帧脉冲与真机截图同指纹）→ wedge 评估 11.9fps → 自动重载 → 重载后 fr11ms 满帧游玩。另修 MuMu 验证环境：夸克浏览器（自带 Chromium 缺 WebAssembly 永远加载中）、`cmd window set-ignore-orientation-request true`+`landscape=1` 破解夸克竖屏锁。

- **v1.9.16**：一卡一卡根治（本地复现闭环 + 五项加固）——v1.9.15 真机日志：`快速唤醒成功（第1轮）→ 帧车夫接管` 新机制全部触发，但游戏仍"一卡一卡"+大旗又弹（F:44——玩了半天游戏内才 44 帧，41 次触摸）。本地复现出根因链条：**触摸同步帧每次都刷新 __xxFrameAt，而车夫让路判据正是"__xxFrameAt 新鲜就让路"——频繁点击时车夫被无限屏蔽，从不补帧**，帧率只剩触摸驱动 ~2fps；心跳 15 帧才上报一次，低帧率下上报间隔 7.5s 拖爆看门狗/大旗死线（复活冲击噪音+误弹重载旗）。本地复现实测同场景 10 秒帧号零推进，修复后 13 秒稳定 312 帧（24fps）。五项修复：①让路判据换新变量 **__xxTickAt**（仅 tick 真出帧时刷新）——触摸帧不再屏蔽车夫；②车夫每拍 8→**24 发**（wedge 态 24fps 底血，文字游戏流畅线）；③Rust 心跳粒度 15→**8 帧**（上报间隔减半，低帧率下不再误判停滞）；④大旗双修：车夫供血中不弹（弹"引擎无响应"纯属误导）+ xxWatch 心跳停滞死线 2.5s→5s；⑤删除车夫的 chaos 豁免（车夫是供血机制不是仿真对象，冻结仿真下也应补帧——chaos 回归断言的点击消费与解冻恢复不受影响）。验证：gate 冻结三时钟+车夫接管+连续触摸，24fps 精确供血（每秒 +24）、无大旗、看门狗零噪音；flow/chaos 回归全绿、桌面冒烟通过。
- **v1.9.15**：点击卡顿根治（v1.9.14 真机日志的最终定案）——用户反馈"点了两下能进游戏，但游戏内点各功能按钮卡一会儿才有反应"，日志呈 9 条`快速唤醒成功（第N轮，+15 帧），重放点击`：游戏内**每次点击**都走了"等 400ms 定时器→冲击→重放"流程。+15 帧这个固定数字暴露本质：wedge 态下 v1.8.8 的三时钟（MessageChannel 4ms/Worker 16ms/setTimeout 16ms）被容器钳到 ~1fps 全部失效（tick 名存实亡，400ms 定时器实际 ~1s 拍才触发=用户感受到的"卡一会儿"），但触摸事件与 ~1s 级 setInterval 照常跑、回调内同步直调 frame() 每次都能推进 future。三项修复：①**触摸同步帧**：手势回调内同步直调 frame()（v1.9.13 曾怀疑"手势栈内出帧被 X5 特殊处理"改为 setTimeout——被本轮数据否掉，setTimeout 在钳制下恰恰是延迟根源）——输入刚注入就当拍消费，实测 2ms 出结果；tick 活着时（__xxFrameAt<60ms）零开销跳过不双驱；②**帧车夫 xxCoach**：唤醒成功不再"打一轮就撤"（实测撤了又死），1s 拍 setInterval 持续补帧 8 发维持 ~8fps 底血，tick 恢复时逐拍让路；③**大旗误弹修复**：旧弹旗条件在"点过一次后挂机 4s"的健康页面也会弹（一次 tap=start+end 计 2 次触摸），加"心跳停滞>2.5s"前置判据；车夫模式下看门狗死线 2.5s→6s（低帧率上报间隔变长）。本地验证：冻结全部时钟后触摸点击 2ms 当拍消费进游戏、无快速唤醒日志；车夫双驱动不崩溃；flow/chaos 回归全绿。
- **v1.9.14**：首击即进（v1.9.13 真机日志定案后的精准优化）——真机日志实锤：`复活冲击无效×3 → 循环复活成功（冲击 +30 帧）`（第 4 轮叩击唤醒循环，随后点击被正常消费进入游戏；大旗误弹是触摸桥判定的竞态）。三项优化：①**触摸驱动快速唤醒**：touchend 后 400ms 检查帧号（心跳上报加密为每 15 帧 250ms），未前进且点击未被消费 → 立即连续叩击（每轮 12 发、间隔 220ms、最多 12 轮）——不再等 2.5s 看门狗，死亡到唤醒 ~1 秒级；②**唤醒后重放用户那一击**：按 __xxLastTouch 原坐标重放完整点击（touch+mouse_down+frame 消费+mouse_up）——真机首击杀死循环的场景下第一击直接生效，无需再点；③复活成功后 4 秒大旗静默期（修真机误弹）。快速唤醒失败 12 轮交回看门狗（重载兜底不变）。本地验证：循环健康时快速唤醒正确按兵不动（不误触）、回归三变体全绿、桌面冒烟 exit=0。

## 构建

```bash
cargo build --release        # 桌面版 target/release/xiuxian.exe
cargo run --release          # 直接运行
```

存档：工作目录 `xiuxian_save.txt`（现实进度 + 道韵 + 烙印 + 宿敌）。

字体为 Noto Sans SC（OFL 许可）子集化内嵌；**文案改动后必须重新执行** `python tools/make_font.py`（扫描 `src/*.rs` 用字生成 `assets/font.ttf`），否则缺字。

## 冒烟验收

```bash
GF_DEBUG=1 ./target/release/xiuxian.exe
```

自动驾驶模式：自动开局、模拟、继承、突破、寻仇、巡检全部面板（含世界地图/洞府经营/秘境远征/嵌套弹层/换图导航/人物页），52 张截图到 `shots/` 后退出，用于无人回归验证。

## 技术

- macroquad 0.4（单依赖），零外部素材：修士立绘/图标/仙山夜景全部运行时像素光栅化，BGM 与音效内存合成 WAV
- 中文 OFL 子集字体内嵌（~426KB）
- 14 模块：`data`（数值表）/ `game`（现实+模拟双轨逻辑）/ `draw`（UI）/ `world`（山河图志）/ `charpanel`（角色面板）/ `menu`（嵌套弹层）/ `npc`（NPC 好感）/ `cam`（信箱相机）/ `art` / `pixel` / `ui` / `sounds` / `save` / `main`
